# Count every CTA tap (5 Nov 2026) - spec for site trackers

Edwin wants every CTA tap counted on the Page One Controller, not just WhatsApp.

## What each tracker must send
POST https://base44.app/api/apps/6ac7f2548a9c3877449e2772/functions/track, JSON body {entity:'CtaClick', site:'<Controller slug>', cta_type, session_id, page_path, ...}.
The track fn checks the browser Origin against the site's domain (hostname must be the live domain) and only stores a fixed field list
(session_id, visitor_id, page_path, referrer, utm_*, device_type, cta_type, enquiry_ref, landing_path, page_referrer, tz, lang, screen, cta_label, ad_click, pages_viewed, secs_on_site, test).

cta_type values (lowercase, [a-z0-9_]):
- `whatsapp` (wa.me / api.whatsapp.com / whatsapp: links, WhatsApp forms). Existing variants like whatsapp_sales still count as WhatsApp. NEVER break the existing WhatsApp count.
- `call` for tel: links
- `email` for mailto: links
- `form_submit` for a real lead/enquiry form being submitted (has phone/email/message field). Search boxes, postal-code finders, filters, newsletter-less UI forms do NOT count.
- `booking` for a real booking button/link (Calendly, Setmore, Fresha, a site's own booking page or booking form). Only if the site really has one.
- Battery Rescue also uses `promo_code` and `out_of_area` (leave as is).

Dedupe per type (1500 ms), not one shared timer, so a call tap right after a WhatsApp tap still counts.

## Test mode (must be in every changed tracker)
```js
var P1T=(function(){var q=/[?&]p1test=1(&|$)/.test(location.search);try{if(q)sessionStorage.setItem('p1test','1');return sessionStorage.getItem('p1test')==='1'}catch(e){return q}})();
// ...and add  test:P1T?1:undefined  to the JSON body
```
The Controller (after Edwin's Publish) stores those taps with flag 'test' and leaves them out of every count. Until Publish, the live
track fn ignores `test`, so after every live test you MUST mark your test rows yourself (see below).

## Rules (do not break)
- Never touch .htaccess. Change only tracker JS (and, only if unavoidable, add a data-cta attribute). Nothing else on the page.
- Never name or credit Edwin Garage on the XADO site.
- Repo drdigital641/edwin-ai-monitor-android is PUBLIC: no secrets.
- One source of truth: if a build script / source folder regenerates the live JS (check /mnt/project-files/<site>/ for build.py or src/), update the source copy too, or the next build overwrites the fix. Note in your report where the source is.
- Small edits: Bridge `invoke_edit_file` (backs up + verifies). Whole file: `invoke_read_file` for sha256, then `invoke_write_file` with expected_sha256.
- If a page loads the JS with ?v=hash cache-busting, that's fine; leave the HTML alone.
- /mnt/project-files is a network mount: use trailing slashes, never search the whole folder, re-read a shared file ~10 s after writing it.

## Live test (one tap per type per changed site)
The Base44 Controller sandbox has a real browser. Run with mcp__Base44__run_command, appId 6ac7f2548a9c3877449e2772:
```
cd /tmp/pw && node tap.js '{"url":"https://SITE/","steps":[{"label":"call","sel":"a[href^=\"tel:\"]"},{"label":"wa","sel":"a[href*=\"wa.me\"]"}]}'
```
If /tmp/pw is missing: `mkdir -p /tmp/pw && cd /tmp/pw && npm init -y && npm i playwright@1.48.2 && npx playwright install --with-deps chromium`, then
write tap.js from /mnt/project-files/tracking/tap.js (copy its text). tap.js opens the page with ?p1test=1, blocks WhatsApp/Calendly navigation,
blocks every non-GET request except the track beacon (so no real enquiry is ever sent), and prevents real form submission. Steps can use
`sel` (click), `eval` (JS in page, e.g. fill a form then `form.requestSubmit()`), `goto` (another page), `force`, `wait`.
Output per step: `cta_type|label|test=1|<status>` (204 = stored; `undefined` status on WhatsApp is normal because the page navigates).
It prints SESSIONS <ids> at the end.

After each run, mark the rows as tests (required until the Controller is published):
mcp__Base44__update_entities appId 6ac7f2548a9c3877449e2772, entityName CtaClick, query {"session_id":{"$in":[...ids]}},
data {"$set":{"flag":"test","cta_label":"qa-test 5 Nov 2026"}}. Then mcp__Base44__query_entities on the same session ids to confirm each type was stored.

For a form test, fill the required fields with obvious test data ("QA test - ignore", test@example.com, 80000000) and call requestSubmit();
tap.js stops it leaving the browser.
